# The Reference Pack — never generate a product without it

**This is a blocking rule, not advice. Read it before every generation.**

> **We never create product images with no reference to previous work that
> already worked. The approved product photograph is ALWAYS reference 1.**

Higgsfield gets better the more proven references it is given. Every time we
have skipped this, the output has been rejected. Every time we have used it,
the output has passed. There are no counter-examples.

---

## 1. The locked masters

### Street sign — approved manufactured-object master
`prompts/wedding-signs/cases/DM-C017-JANNAWAY/validated-evidence/01-approved-product.jpg`

A real photograph of a real Daisy Maison sign held in the workshop. It carries
the truths a model cannot invent: real material and sheet depth, the shaped end
areas, the true black border width, mounting holes, surface reflectance, hand
contact and finger occlusion, contact shadows, grain and lens character.

**This is reference 1 for every street-sign image, forever.** It is the locked
authority for the *object*. It is never regenerated, never replaced by a
description, and never omitted "just this once".

## 2. The rule that keeps being broken

From the validated case's own fault-line table:

| Fault line | Validated fix |
|---|---|
| **Flat SVG was treated as the whole physical product** | **Lock one real Daisy sign as the manufactured-object master; the SVG changes printing only** |

Handing a model only the flat artwork and asking it to "make it real" produces a
fake-looking sign every time. It has no idea what the object is made of. The
approved photograph is what tells it.

## 5. Pre-flight checklist — answer before any product generation

1. Am I passing the **approved product photograph** as reference 1? If no — stop.
2. Am I using a **validated prompt** from the case folder, with only the wording
   changed? If no — stop.
3. Is the sign face from **`build.py`**, not a description or a model's guess?
4. Have I added every supporting construction reference that applies?
5. Is this a **batch of four** for a human to choose from?
6. Have I preflighted the cost with `get_cost:true`?

If any answer is no, the generation does not run.
