# Daisy Maison prompt engineering library

This is the permanent Jarvis memory for generative prompts that have survived a
complete Daisy Maison production workflow.

A promising still is not a successful case. A case is added only after the
intended final asset exists, has been technically checked, and has its prompt,
references, settings, IDs, costs, fault line and correction preserved together.
Max's creative approval and publication approval remain separate explicit
gates.

## Libraries

- `wedding-signs/` — the **Wedding Sign Engineering Prompt Workflow**
  case library: synthetic Max, the white wedding-sign LightBurn system,
  human-approved native product imagery, genuine generated motion and QC.
  Product-surface overlays are forbidden. Coloured and non-wedding sign
  families are not yet validated.

## Evidence rule

Every case must contain:

1. the exact successful prompt;
2. the reference-role map;
3. the generated image or representative visual evidence;
4. model, settings, job IDs and known cost;
5. the failure or fault line that preceded the result;
6. the fix that was actually tested;
7. the finished output, human product-realism decision and QC result;
8. an honest note about anything the result still did not obey.

Do not create placeholder “successful” cases to make the library look fuller.
The engineering map becomes useful only when five or six independently proven
cases exist.

Rejected cases may be kept only in an explicitly labelled failure section.
They must explain why they failed and must not be reused as recipes.
