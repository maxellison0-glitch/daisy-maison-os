## 📚 Lesson of the Day

### Conversion API (CAPI) — Server-Side Tracking

**Callback:** In the Standard Events lesson (31 Aug), you learned that Facebook's pixel fires events (ViewContent, AddToCart, Purchase) from the shopper's browser. CAPI is the server-side companion that fires the same events from Shopify's server directly to Facebook, bypassing browser-level tracking blocks.

Since iOS 14.5 (April 2021), Apple lets users opt out of browser tracking. When they do, the pixel stops reporting their purchases — Facebook under-counts conversions and optimises away from what's actually working. CAPI fixes this: when someone buys on Shopify, two signals fire simultaneously — the pixel (browser-side, blockable) and CAPI (server-side, reliable). Facebook deduplicates them using a shared event_id so no purchase is double-counted. Result: Facebook sees ~95% of purchases instead of ~60–70% on pixel alone.

**Why this matters now:** When you take the ads in-house, verify CAPI is active. If Daryl set it up through Shopify's native integration (Settings → Customer events → Facebook & Instagram), it should already be working. If it's missing, every optimisation decision Facebook makes is based on incomplete data.

**ASK DARYL THIS:** "Is the Conversion API active on our Facebook pixel, and are events deduplicating properly?" A good answer names the integration method (Shopify native, Conversions Gateway, or manual). An evasive answer is "the pixel is fine" without mentioning CAPI — that likely means it's not set up. Only ask Daryl things that require his judgment or access — this is one of them, since verifying deduplication needs the Events Manager UI.

**You should now be able to** check Events Manager → Data Sources → your pixel → Overview tab and see whether events arrive via "Browser" only or "Browser and Server" — the latter confirms CAPI is live.
